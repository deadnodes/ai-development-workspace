# Полный backup и перенос между экземплярами

Control Plane сам упаковывает состояние в `*.rcp.json.gz` и распаковывает при восстановлении. Архив содержит **весь экземпляр**: Products, конфигурацию, registry, связи, фичи, интеграции, memory/handoff, результаты проверок, findings, ревизии, композиции, релизы, операции и audit. Это полный перенос application state, не Git-зеркало конфигурации.

Архив не содержит внешние Git-репозитории, image bytes, файлы по artifact URL, PostgreSQL users, Kubernetes Secrets, PEM-файлы или API token сервера. Ссылки на credentials сохраняются. На целевой установке отдельно подключи DB URL/API token и секреты по тем же путям. Ранее наблюдённые Git/Flux/runtime статусы сохраняются как исторические наблюдения, а не свежая проверка доступности.

## MCP

Агент подключается к исходному и целевому MCP-серверам с разными именами и credentials.

1. На источнике: `get_backup_capabilities {}` — формат, лимиты и политика.
2. На источнике: `create_backup {"actor":"agent/migration"}`.
3. Ответ содержит `format`, `sha256`, `bytes`, `archive_base64`.
4. На **пустом** целевом экземпляре:

```json
{"actor":"agent/migration","sha256":"CHECKSUM_FROM_SOURCE","archive_base64":"BASE64_FROM_SOURCE"}
```

Это аргументы tool `restore_backup`. Дождись `restored: true`; затем `get_state` и `resume` нужной Feature. Повторный импорт в уже заполненный экземпляр будет отклонён, включая случай потерянного ответа: сначала прочитай целевое состояние и restore audit, не очищай БД.

Для большого архива агенту удобнее передать файл по HTTP с помощью скрипта ниже, чем помещать base64 в контекст разговора. Не выводи архив в чат или логи.

## Файловый backup / перенос агентом

Нужен Node.js 22+. `RC_TOKEN` при необходимости поступает из secret environment отдельно для каждого вызова. Из корня репозитория:

```sh
# Источник: адрес доступного экземпляра или локального port-forward.
RC_URL=http://127.0.0.1:8090 RC_ACTOR=agent/backup \
  node scripts/backup.mjs export .local/backups/project.rcp.json.gz

# Цель: ДРУГОЙ, пустой экземпляр (например второй port-forward).
RC_URL=http://127.0.0.1:8091 RC_ACTOR=agent/migration \
  node scripts/backup.mjs restore .local/backups/project.rcp.json.gz
```

Скрипт сохраняет gzip и соседний файл `.sha256`, проверяет checksum при передаче и отказывается перезаписывать существующий backup. Переноси оба файла. Сервер выполняет gzip-сжатие/распаковку; скрипт только передаёт bytes. Для повторных backup используй новые имена с датой. Успех экспорта не означает перенос: проверяй ответ restore и целевой контекст.

Эквивалентные HTTP endpoints (тот же shared bearer token, что API/MCP):

| Запрос | Заголовки / тело |
| --- | --- |
| `POST /api/backups/export` | `X-RCP-Actor`; ответ gzip, checksum в `X-Backup-SHA256` |
| `POST /api/backups/restore` | `X-RCP-Actor`, `X-Backup-SHA256`, `Content-Type: application/gzip`; тело — gzip bytes |

## Восстановление и параллельная работа

- Экспорт читает согласованный снимок PostgreSQL. Работа источника может продолжаться; изменения после снимка в него не попадут.
- Для окончательного переноса останови запись агентов/пользователей в источник, дождись завершения активных операций, сделай финальный backup и переключи агентов на цель. Сам экспорт не блокирует новые команды на всё время миграции.
- Restore допускается только в пустой application state. Проверка пустоты и импорт проходят в одной транзакции; два одновременных restore не могут смешаться. Существующая история никогда не заменяется и не объединяется автоматически.
- Все исходные ID, временные метки, порядок записей и audit сохраняются. Добавляется событие `restore_backup` с checksum и actor.
- PENDING/RUNNING операции на цели получают CANCELLED. Их исходные полные записи сохраняются в restore audit, добавляется шаг отмены. Запущенный на источнике CI от этого не останавливается. Проверь внешние эффекты до нового deployment; восстановленный worker не должен автоматически повторять чужую работу.
- Восстанавливай доверенные архивы той же версии приложения или совместимой более новой. Проверяются gzip/CRC, SHA-256, версия формата, размер, неизвестные поля и структурные ID/ссылки. Это не криптографическая подпись и не полная повторная валидация исторических команд по текущим правилам.

## Лимиты и хранение

MVP: максимум 8 MiB сжатого архива и 64 MiB распакованного JSON. Превышение даёт ошибку, не усечённый backup. Для более крупных экземпляров пока используй PostgreSQL backup/restore с эксплуатационным контролем worker; ограничения могут быть расширены отдельной потоковой реализацией.

Gzip — сжатие, не шифрование. Архив содержит приватную историю, конфигурацию и любые данные, ранее записанные пользователями в текстовые поля. Храни его в закрытом, при необходимости зашифрованном backup storage. Secret refs не раскрываются самим приложением, но произвольно записанный в memory секрет также попадёт в полный backup.

Автоматическое расписание, retention, object storage и слияние двух историй не реализованы. MCP/API и скрипт позволяют агенту выполнить backup и перенос сейчас. Полный PostgreSQL/PITR backup остаётся отдельным инструментом эксплуатации.
